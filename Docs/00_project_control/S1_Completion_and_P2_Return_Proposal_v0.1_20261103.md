## 2. S1はどこまでやれば十分なのか？

現在、バックアップ対象となっているのは、P2のRegressionに関係する5ファイルです。

- Regression生ログ3件
- Production Source ZIP 1件
- 実行Workbook 1件

バックアップ方式もすでに決定しています。

**Primary（非公開保存先）＋BitLockerで暗号化したUSBバックアップ**です。

現時点では、USBの暗号化設定まで進み、Precheckや原本コピー、復元試験が残っています。

私が考えるS1の必要十分な完了条件は次の4つです。

1. PrimaryとBackupの保存先・アクセス条件が確認されている。
2. 5ファイルを両方に保存し、SHA-256一致を確認できる。
3. Backupから5ファイルを復元できることを確認する。
4. Archive Manifestを更新し、G2で正式承認する。

**ここまでできたら、バックアップの検討は終わりにしてよいと思います。**

新たなバックアップツールの導入、バックアップ世代管理、自動化、保管ルールのさらなる精緻化などは、現時点では不要です。

なお、Public GitHubへのPush禁止は、現在のローカル履歴に個人情報を含むRaw Evidenceがあるため、引き続き維持する必要があります。

## 4. 私が気になっていること

現在の進め方には、一つリスクを感じています。

それは、次々に発見される周辺課題を、すべて解決してから次に進もうとしていることです。

例えば、
```
P2を完了したい
    ↓
Evidenceの保全が必要
    ↓
保管場所のルールが必要
    ↓
バックアップが必要
    ↓
USBの暗号化が必要
    ↓
アクセス権限の確認が必要
    ↓
バックアップの運用ルールが必要
    ↓
さらに新しい課題が発生
    ↓
本来のP2が進まない
```

一つ一つの判断は合理的でも、全体としては効率を損なう可能性があります。

これは、以前から重視してきたYAGNI（必要になるまで作らない）とも関係します。

そこで今後は、**新しい課題が出たときに、それがP2完了のBlocking要因なのかを判断する**ことを推奨します。

Blockingでなければ、課題を記録して先へ進む。

これを徹底すれば、周辺課題に開発が引きずられにくくなります。
