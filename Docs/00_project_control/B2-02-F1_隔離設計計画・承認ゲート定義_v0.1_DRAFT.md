## 2. 設計候補と採用判断の境界

### 2.1 A＋C1（推奨候補、未選定）

- **A**：検証PC全体に対するネットワーク制限。OneDrive／Google Drive／外部接続を含め、Codexを使わないオフライン時の手順を設計する。
- **C1**：新規のローカル**標準ユーザー**を専用に使用し、Production関連資源へのアクセスを制限する。管理者アカウントの非昇格セッションと標準ユーザーアカウントを混同しない。
- 専用ユーザーは`Administrators`や`CodexSandboxUsers`等、アクセスを与え得る既存主体への不要な所属を避ける**設計候補**とする。非所属だけでは隔離PASSを宣言しない。
- Production Clone／Workbook／Archiveの権限変更を前提に成立させない。もし変更が必要なら**STOP・別途設計判断**とする。
- Excel、VBE、制御プロセス、Windowsユーザーの**実行主体**を別々に識別する。Codexツールの実行先と操作中のPCが同じとは推定しない。

### 2.2 A＋C2（フォールバック候補、未選定）

- A＋C1の保護境界が成立しない場合などに、隔離VM等の選択を**再評価する候補**。
- Windows 11 HomeにWindows Sandboxが利用できると決めつけない。VMのライセンス、ホスト共有、クリップボード、ネットワーク、Office/VBE実用性は別途レビュー。
- C1が不成立でもC2へ**自動移行しない**。選定は別途ユーザー判断。

### 2.3 方式選定Gate（将来のDecision）

採用検討の入力条件：対象資源マップ、ACL・共有・同期境界、標準ユーザー実行条件、Office使用条件、F1-3～F1-5設計、既知リスク、必要操作の承認単位。

- `SELECT_A_PLUS_C1`：入力条件が揃い、アクセス遮断手段と検証手順が具体化したときに、ユーザーが**明示的に採用**。
- `SELECT_A_PLUS_C2`：代替案が具体化し、ユーザーが明示的に採用。
- `REVIEW_REQUIRED`：根拠不足、ライセンス・隔離上の未解決事項あり。
- `BLOCKED`：保護資源への無承認変更が不可避、安全な検証方法を構成できない等。

**現時点：`IsolationMethodSelected: NONE`／`IsolationEstablished: NOT_VERIFIED`。**

## 5. AUTH-01～AUTH-06：承認ゲート定義（再構成案）

> 各AUTHは**個別のユーザー明示承認**を要求する。ドラフト作成／レビュー・過去のP01コマンド承認はどのAUTHにも効力を与えない。必要な場合、1 AUTH内もさらに細分化して個別承認する。全AUTHの現在値は`NOT_GRANTED`。

| Gate | 将来承認する可能性のある操作 | 必須の前提・Evidence | 承認前／異常時の停止条件 | 現状 |
|---|---|---|---|---|
| **AUTH-01** | 既存Excel/VBEを**通常手順で安全に終了**（必要時のみ） | 対象PC・プロセス実体・未保存作業なし・取得すべきEvidenceなし・終了対象を明示 | PIDの過去申告を現在PIDとみなさない。Workbook保存や強制終了は自動許可しない | `NOT_GRANTED` |
| **AUTH-02** | 専用ユーザーの作成・所属設計、C1アクセス隔離、Aのネットワーク制限などの**限定環境構築** | A＋C1正式選定、F1-1/2/3/4レビュー、保護資源の非変更原則、戻し方・停止条件、実行PC・権限 | 予期しないACL変更、ProductionのOpen／Copy、認証要求、影響範囲不明ならSTOP。ユーザー作成・ネットワーク設定等は更に分割承認可能 | `NOT_GRANTED` |
| **AUTH-04** | Evidence場所・アクセス・保管・収集条件の確定、および必要最小限の準備操作 | F1-5案、Private/Public区別、期間、権限、作成するフォルダー・ファイルを明記 | 場所・保存内容・保管期間未決定なら操作しない。**AUTH-03実測より前に実施・評価が必要** | `NOT_GRANTED` |

### 5.1 Gateの依存関係（固定順序と例外）

```text
F1-READ-01 (COMPLETE_WITH_LIMITATIONS) ─┐
F1-2       (DESIGN_REVIEW_COMPLETE...) ─┤
F1-1の残件／F1-3／F1-4／F1-5 ──────────┤
                                     ▼
                     A+C1正式採否（まだNONE）
                                     ▼
                         [必要に応じAUTH-01]
                                     ▼
                     AUTH-02：限定的な環境構築
                                     ▼
    AUTH-04：Evidence条件を確定（AUTH-03の前は必須）
                                     ▼
                     AUTH-03：隔離の実測検証
                                     ▼
       AUTH-05：Fixture作成 → 安全性Preflight Compile
                                     ▼
                AUTH-06：現行Production Compile
                                     ▼
                      S5-C → S5-D → S5-E
                                     ▼
                P2 Phase Exit / CP-P2別判定
```

**注意**：これは論理的な依存関係であり、AUTH番号の大小順ではない。Evidenceの取得がAUTH-02の事前／同時に必要な場合は、**AUTH-04を前倒し**し、承認単位を明示する。AUTH-01は既存Excel/VBEを閉じる必要がある場合のみ。S5-C以降もそれぞれ別承認。

### 5.2 各AUTHの承認記録に必須のフィールド

```yaml
AuthorizationID: AUTH-XX
AuthorizationStatus: NOT_GRANTED  # 将来の承認時にのみ更新
TargetPC: S5B-TestPC-01
TargetIdentityAndPrivilege: NOT_VERIFIED
ActionScope: UNDEFINED
ExplicitlyAllowedOperations: []
ExplicitlyProhibitedOperations: []
ExecutionToolOrManualMethod: UNDECIDED
ExecutionTargetBinding: NOT_VERIFIED
PreconditionsAndEvidenceIDs: []
ExpectedMutationOrReadScope: []
StopConditions: []

ApprovalByAndTime: NOT_RECORDED

```

禁止：未承認実行、意図しない対象PC上での代理実行、隠れた追加照会、エラー時の自動再試行、無断の設定緩和・権限昇格・Rollback。

## 7. 安全性原則・判定規則

1. **Fail closed**：承認・対象・実行主体・必要Evidenceのいずれかが未確認なら実行しない。`UNKNOWN`をPASS扱いしない。
2. **非変更とRead-onlyは別**：設定変更がないだけでは、機微な情報や保護ファイルへの過剰読取りが正当化されない。
3. **起動安全性とCompile成功は別**：VBEを起動できる・DLLがある・Fixtureで成功した等を、現行Production Compileの安全性／PASSへ転用しない。
4. **Excel Automationの安全性の限界**：`AutomationSecurity=ForceDisable`のみでXLMマクロ全体を安全化できるとは扱わない。`EnableEvents=False`を設定してもExcel起動時点の処理を遡及的に抑止したことにならない。`Workbooks.Open(UpdateLinks:=0,ReadOnly:=True,AddToMru:=False)`でデータ接続・外部動作すべてが抑止されるとは断定しない。`AskToUpdateLinks=False`の自動リンク更新リスクを無視しない。
5. **マクロセキュリティ緩和禁止**：Trust Center／Trusted Locations／VBOMの変更は本書によって認めない。
6. **証拠階層**：`USER_ATTESTED`、`USER_MANUAL_GUI`、`USER_MANUAL_COMMAND`、`CODEX_OBSERVED`、独立技術観測、歴史的Evidenceを区別する。
7. **原本の優先**：現行Production Workbookは、過去の正本識別と現在の証拠を改めて照合し、テストPC CloneやOneDrive上の同版Workbookへ自動切替しない。
8. **文書／Baseline**：Plan・Project Controlの状態更新と正式仕様／Baseline変更は別承認。
9. **STOPの後**：自動再試行・自動Rollback・不承認の代替手順・環境変更は行わない。必要な場合、原因・範囲・限定承認案を提出する。
