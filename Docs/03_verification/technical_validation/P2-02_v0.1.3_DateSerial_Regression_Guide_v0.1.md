# P2-02 v0.1.3 Production Correction / Date Serial Regression Guide v0.1

## Scope

P2-03 v0.1.2 is unchanged.

Correction target:

`modSyncEngine_P2-02_v0.1.2_CP932.bas`

Output:

`modSyncEngine_P2-02_v0.1.3_CP932.bas`

## Root Cause

The production carrier reads Excel cells using `.Value2`.

Therefore date cells may arrive at P2-02 as numeric Excel Date Serial values rather than `Variant/Date`.

P2-02 v0.1.2 used `IsDate()` as its initialized Detection History validation and rejected the real carrier representation.

## Correction

`ValidateMetadataState` now validates initialized timestamps through:

`TryGetMetadataDateValue`

Accepted:

- VBA Date
- Excel numeric Date Serial represented as:
  - Byte
  - Integer
  - Long
  - Single
  - Double
  - Currency
  - Decimal
- only when `CDate()` succeeds

Rejected:

- Empty when only one timestamp is Empty
- Null
- Error
- String date
- invalid non-date String
- numeric values that cannot be converted to Date

Blank / Blank remains handled earlier as valid Detection History Uninitialized.

## No Change

- BuildSyncDiff public signature
- SyncDiffResult shape
- classification rules
- TemplateLocation / Detection History independence
- bootstrap behavior
- SyncTimestamp source
- P2-03 v0.1.2
